# Compliance checklist

How each launch requirement is met in this codebase, and what the business owner still has to do. "✅ Built" means implemented and tested here; "👤 Owner" means it needs real-world information or a decision only you can make.

This is engineering work, not legal advice. Have a qualified lawyer review the policies for the countries you sell in before launch.

| # | Requirement | Status | Where / how |
|---|---|---|---|
| 1 | **Privacy policy** | ✅ Built · 👤 fill details | `legal/privacy-policy.md`. Shown in the app (Settings → Legal), on the website (`/privacy.html`) and on first launch. Describes the data the code actually handles: no account, local-only storage, API key in Keychain/Keystore (web: memory only), messages sent directly to Anthropic, website forms, retention periods, rights, CCPA statements. |
| 2 | **Terms of service** | ✅ Built · 👤 fill details | `legal/terms-of-service.md`. Covers eligibility, price, the user's own Anthropic account, AI-output disclaimer, acceptable use, liability (with consumer-law carve-outs), changes, governing law. |
| 3 | **Refund policy** | ✅ Built | `legal/refund-policy.md`. App is free; store purchases → Apple/Google processes; direct purchases (including source-code licences) → 14 days, no reason or fee required, EU/UK digital-content withdrawal rule explained. |
| 4 | **Cookie policy** | ✅ Built | `legal/cookie-policy.md`. Lists the single storage item the website uses (`cd_consent`) and explains the app's local storage. |
| 5 | **Cookie consent banner** | ✅ Built | `apps/web/src/consent.js` + `_layout.html`. Shown before anything optional runs. "Reject all" and "Accept all" are identical in size and style; optional categories default to off; choice is re-asked after 12 months; "Cookie settings" link in every footer to change or withdraw. Zero cookies are set by default (verified in a headless browser). |
| 6 | **Check form consents** | ✅ Built | Every consent checkbox starts **unticked** and is required, and consent is never bundled: app first run (age + terms, separate boxes, button disabled until ticked: `apps/mobile/src/app/welcome.tsx`); newsletter (separate opt-in + double opt-in confirmation email, consent wording and timestamp recorded: `apps/server/lib/handlers.mjs`); privacy-request form (authority confirmation only). The server rejects submissions without the explicit value (tested in `scripts/tests/server.test.mjs`). Policy-version changes force re-acceptance. |
| 7 | **No unnecessary data** | ✅ Built | The app has no account, no analytics, no device IDs. The website stores only email + request type/details, or email + consent record. No IP logging; rate limiting uses an in-memory salted hash. Unconfirmed sign-ups deleted after 7 days; closed requests after 24 months; unsubscribing deletes the address. Free-text capped at 2,000 characters. Android backups disabled so data doesn't leave the device. |
| 8 | **Audit third-party SDKs** | ✅ Built | `legal/third-party-sdk-audit.md` (also in the app and on the website). `npm run notices` lists every shipped package and **fails the build** on an unreviewed licence. No analytics, ads, crash-reporting or tracking SDKs. Unused template packages (`expo-symbols`, `expo-image`, `expo-device`, `expo-web-browser`, `@expo/ui`, `expo-glass-effect`) were removed. |
| 9 | **Remove dark patterns** | ✅ Built | Equal-weight accept/reject; no pre-ticked boxes; no confirm-shaming; destructive actions name exactly what will be deleted and default to Cancel (`apps/mobile/src/lib/confirm.ts`); unsubscribe is one click, always succeeds and needs no login; deleting all data is two taps from Settings; no nag screens or fake urgency. |
| 10 | **Remove hidden fees** | ✅ Built | Price is stated on first launch, the website and in the Terms: free, no subscriptions or in-app purchases. AI usage is billed by Anthropic and the app says so, shows token counts and an estimated cost per reply (labelled as an estimate with the date the prices were checked: `apps/mobile/src/lib/models.ts`). |
| 11 | **Remove fake reviews** | ✅ Built | There are no testimonials, ratings, user counts or review widgets anywhere. Add real reviews only with the reviewer's permission. |
| 12 | **Remove unsupported claims** | ✅ Built | Marketing copy describes only features that exist. No "#1", "best", "secure"/"guaranteed" or productivity claims; accessibility statement says "self-assessed" and lists known limitations; the website says store availability is not yet announced. Footer states Crewdeck is not affiliated with Anthropic. |
| 13 | **Accessibility alt text** | ✅ Built | Website logo is decorative (`alt=""` next to the visible name); app icons/avatars are hidden from screen readers because a text label is always next to them; every control has an accessible name, role and state; headings are marked as headers; live regions announce form results and "agent is responding". |
| 14 | **Fix colour contrast** | ✅ Built | Palette redesigned and **automatically checked**: `npm run check:contrast` verifies 66 pairs (text ≥ 4.5:1, borders/focus ≥ 3:1) in both themes for app and website, plus every avatar colour. Part of `npm test`. |
| 15 | **Keyboard navigation** | ✅ Built | Website: skip link, visible `:focus-visible` ring, logical order, cookie banner first in tab order, Escape closes it once a choice exists, accessible error messages that move focus to the first invalid field. | 16 | **Add business details** | ✅ Built · 👤 fill details | One file: `business.config.json`. ## Owner to-do before launch

1. Fill in every placeholder in `business.config.json` and the bundle IDs in `apps/mobile/app.json`; run `npm run check:business` until it passes, then `npm run build:legal`.
2. Have a lawyer review `legal/*.md` for your jurisdictions (especially governing law, liability cap, and whether you need EU/UK representatives).
3. Choose an email provider; set `SMTP_URL`, sign a data processing agreement with them, and name them in `business.config.json`.
4. Search trademarks for the name "Crewdeck" in your markets before you invest in the brand.
5. Complete the App Store privacy label and Google Play Data safety form; see `docs/APP_STORE.md`.
6. Commission an independent accessibility audit when you can, then update the accessibility statement.
